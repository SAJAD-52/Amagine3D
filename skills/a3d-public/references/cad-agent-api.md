# Structured task CLI

`a3d agent` wraps the existing CAD builders and validators with bounded JSON
results. It uses the same managed Python and session permissions as the other
CLI commands. It adds no service or dependency. Authoring uses editable
parameterized `.a3d.json` designs or the existing Python source workflow.

Use one operation and one JSON request, or put that request in a workspace file:

```bash
a3d agent context
a3d agent capabilities '{"symbols":["SelfTappingScrewPair.bind","BuildSession.cut"]}'
a3d agent validate '{"source":"model_build.py","intent":"model_intent.json"}'
a3d agent build '{"phase":"draft","source":"model_build.py"}'
a3d agent build --args-file compile-request.json
```

A compile request requires `phase: "compile"`, `source`, `intent` and `scene`,
or `design`, `revision` and `intent`. Design mode generates its scene and
executes an immutable snapshot through the same compiler. Read
[Parametric design](parametric-design.md) for local queries, batched edits,
supported operations and revision semantics.
The scene may be generated by the source. Optional `timeoutSeconds` is between
1 and 5400; draft defaults to 120, compile to 5400. All paths, including request
files and report references, stay inside the current session workspace.

Exit codes are 0 for a successful operation, 1 for reported failed checks,
and 2 for an invalid request or API error. Stdout is one JSON value. Build stage
logs are saved locally; `context` exposes the running attempt and its log path.
Keep the shell tool's real execution handle and exit status for long builds.
Cancellation terminates the source process group and releases the writer lock.
An interrupted attempt is explicit in context; do not infer a successful build.

## Results and evidence

CAD delivery and display have independent `artifactStages`: `geometry`, `cadExport`,
`tessellation`, `display`, `preview`, `manufacturing` and `visualReview`. A passed
`cadExport` has STEP readback evidence against the original BRep. A failed display
retains that bound STEP. When manufacturing passed but PNG evidence failed, the
run is `awaiting-preview`, `pass=false`, and context provides `nextDisplay`.
Drafts never establish
manufacturing acceptance. Managed compile attempts retain separate output folders.

To retry only the derived display, use the exact run report and its SHA:

```bash
a3d agent display '{"report":".a3d-agent/runs/RUN.json","sha256":"REPORT_SHA"}'
```

This reads audited CAD objects, verifies source/intent/design bindings and STEP
geometry, then builds STEP-backed images without executing source or changing STEP.
It preserves physical/reference roles and appearance. Changed inputs, empty CAD
or an unverified CAD stage are rejected. A draft remains a display draft. A compile
in `awaiting-preview` can reuse its passed manufacturing evidence only while the
parent report, every input, STEP/STL/3MF output, intent lineage and capability
version still verify. The successful retry returns `awaiting-visual-review` and
records `manufacturingEvidence.parentReport`; installation and manufacturing
checks are not rerun. A changed proof cannot be reused or promoted.

## Image handoff and review status

`context`, `inspect`, and build/display summaries expose one usable image binding
as its full `path` and SHA-256. The main `preview` is preferred when its bytes
still match; otherwise a current `diagnosticPreview` may be exposed and is marked
diagnostic. If neither image matches, the summary omits both paths and reports
`stale-or-missing`. Draft reports may keep image bindings in the exact run's
`state.json` outputs rather than their report body; lookup matches both report
path and hash and never borrows another run's image.

A current image path does not mean it was opened or visually reviewed. Use the
image only when it can affect the next decision, and inspect `previewScope` and
the bound report before making claims. Historical images and local diagnostic
images remain explicitly labeled; a partial scope cannot establish whole-part
status. When a compile already has a current image, review it instead of running
a draft to obtain another image. Use `agent display` only to retry a failed
derived display; it reuses manufacturing evidence and does not rerun checks.

When review findings affect follow-up work, optionally record a small agent checkpoint:

```bash
a3d agent checkpoint '{"report":".a3d-agent/runs/RUN.json","sha256":"REPORT_SHA","observations":["screen opening visible"],"todo":["validate insertion clearance"],"functionalReady":true}'
```

Each list contains at most six short strings. The checkpoint binds the report,
inputs and capability version. Each string is at most 300 characters. `functionalReady` suggests declaring the contract
and compiling before more aesthetic edits; it does not change machine acceptance
or certify image review. Recovery exposes current checkpoints, `nextAction`,
current validation and exact `nextInspect`/`nextDesignRead` requests. Another
design's failures remain history and do not route current work.

Active intent identity supplements active source/design identity for runs that
bind an intent. Changing only the contract file makes previous formal acceptance
historical; an intent-free draft remains a current geometric draft. A fresh full
validation exposes `nextBuild` for compile when all required inputs are known.
Static validation or display retry cannot erase a current manufacturing failure.
Recovery retains its exact issue query until the corresponding checks pass;
display-only success resolves only the matching display failure.

A result carries status, run identity, acceptance/visual flags, issue counts,
preview bindings, a full report reference and a page. Issues put errors before
warnings. Known placement checks show offenders and count normal observations.
Printability findings retain measurements, risk bounds and coordinate frames;
large feature lists remain candidates, never proven causes. Identical explanation
text may point to `sameAs` while different frames and measurements remain distinct.

Large fields become references containing `field` (a JSON pointer), `type` and
optional `count`. They are complete references, not shortened field contents.
Resolve them against the result's `report`:

```bash
a3d agent inspect '{"report":"RESULT.json","sha256":"REPORT_SHA256","field":"/inputBindings/source"}'
a3d agent inspect '{"report":"RESULT.json","sha256":"REPORT_SHA256","issueId":"ISSUE_ID","field":"/observed"}'
```

With no field/issue selector, inspect returns the issue summary. Follow
`page.next` as `cursor` using the same report, SHA and selector. A changed report
or different selector rejects the old cursor. Large strings return explicitly
labelled `textChunk`, `textOffset` and `textLength`; ordered pages reconstruct the
original value. Whole reports are never changed to make output fit.
Each page also returns `page.nextRequest`, complete arguments for `agent inspect`.
This preserves the resolved field even when the first query used `issueId`.
The final page returns null. Do not rename cursor to page or omit its field.

Task results are snapshotted under `.a3d-agent/runs` so a later compile cannot
replace evidence referenced by a previous issue query. Legacy result files can
also be inspected, but must be rereferenced if their bytes change.

## Context, capabilities and reuse

Read context after compaction or continuation instead of repeating help and the
skill. It reports the capability fingerprint, signatures previously provided,
latest build and whether bound inputs still match. An old session without API
state exposes its known legacy result with freshness unknown/false.
When a report is available, `nextInspect` is a complete JSON request for
`a3d agent inspect`. Reuse that path/hash and follow page.next; do not invent a
run-specific filename, pipe output through head/tail or write a report parser.
Recovery includes these short conventions and preserves unresolved warning scope.
`lastFailure` retains exact failure evidence and whether its inputs still match;
`validation` records the most recent static check. `nextDesignRead` and
`nextValidate` are ready-to-use arguments when available. A design summary lists
parameter IDs, node IDs and `requirementNodes` for local queries. `suggestedPhase`
describes the evidence state, not a gate or a manufacturing acceptance claim.

Submit needed capability names together; there is no name-count limit. Requests
remain limited to 64 KiB, and results paginate by actual output size. Follow
`page.nextRequest` rather than splitting requests by a fixed number of names.
Large `fieldTypes` or name indexes use inspectable references to the saved report.
Signatures and documentation come from installed/public implementation;
parameter choices come from literal validation guards. Unknown symbols return
suggestions. Large contracts are
inspectable through the saved capability report. Returning a symbol or an image
path does not mean that all documentation or that image was read.

`designOps` queries use the typed operation registry. Context retains the
supported contracts actually returned in `previouslyProvidedDesignOps`, and
the design summary lists its used operations. A changed capability version
invalidates that history; unsupported or omitted schemas are never marked read.
The DSL registry now includes controlled collar/screw connections and installation
declarations. `operationNames` is a small exact-name index, not a claim that its
full contracts were read. Unsupported queries suggest related names without aliases.
`fieldTypes` supplies the requested axis, selector, depth, section and frame
structures, examples and legal choices. Connection operations include short
intent binding rules, including required self-tapping locator_pairs. Context's
`capabilityReports` locates delivered contracts; pages read through inspect also
update the delivered-operation history when their version still matches.

Validate design and intent together before final compile:

```bash
a3d agent validate '{"design":"model.a3d.json","revision":"REVISION","intent":"model_intent.json"}'
```

Validate and build share the same static checks for physical parts, requirement
owners, missing physical bindings, connection identities/endpoints, installation
declarations and supported color export. Independent problems are reported in
one result before CAD starts. This does not prove geometric fit or manufacturing.
Common feature/interface/color shape errors include JSON field pointers, expected structure/choices and
repair hints at the validator that owns the rule. The complete assembly intent
example is `$AMAGINE3D_SKILL_DIR/examples/installed_module_intent.json`.
Validate also checks recorded intent lineage without freezing a new contract or
committing a revision. A previously frozen file's byte change fails validation
before another CAD run. Compile saves exact original-byte copies under
`.a3d-agent/intents/<SHA256>.json`; history and overwrite findings bind them by
path/SHA. For an accidental overwrite, restore that verified copy byte for byte.
Genuine revisions use new files linked to the current frozen parent. Legacy
histories gain byte snapshots only while the original file still verifies;
unavailable legacy bytes are never reconstructed from the parsed JSON snapshot.
Intent-bound drafts can reserve geometry before final features/interfaces are
complete; present requirements still need valid owners. Full validation and
compile require every declared physical binding and supported export.

Only a successful draft or automatically passed compile with matching source,
intent, scene/profile, capability version and output hashes can be reused.
Local workspace Python imports (for example `controls.py`) are bound too.
Declare other data inputs with `dependencies: ["input.json", ...]`; arbitrary
Python file reads are not automatically inferable. Changing a declared input
or a local parameter module invalidates reuse. Inspect `/taskInputBindings`
for the full task input list; `inputsCurrent=false` means the saved result does
not describe all current inputs even if its automatic checks originally passed.
Failed, missing, stale or interrupted evidence never blocks a retry. A reuse
retains the original runId and acceptance flags. A draft and a diagnostic preview
are never manufacturing results. Automatic compile pass still requires visual
review and does not establish delivery readiness.

## Measurements and cost accounting

`a3d measure MODEL.step --section-z HEIGHT` returns numbers by default.
`--preview` renders only requested sections from the same already measured faces.
The image is an illustrative sampled outline; the bound report contains exact
section measurements. Finite sections do not establish global minimum walls.
Measurement reports are queryable through `a3d agent inspect`.

The task API records operation sizes, duration and reuse in workspace metrics.
Chat attempts independently record the five SDK token counters and their true
outcome, including failures/cancellation. Missing counts remain unknown; cached
input and reasoning output are subsets of totals. No price or cost saving is
inferred from character counts, fewer files, or offline replay alone.
